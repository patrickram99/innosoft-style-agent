## 1. Historia de usuario

**Como** plugin OJS, **quiero** enviar un PDF y sus metadatos a un endpoint del agente, **para** iniciar el análisis.

## 2. Propósito

Es el punto de entrada de todo el flujo: recibe el manuscrito, lo valida mínimamente, lo persiste y devuelve un identificador para que el procesamiento continúe de forma asíncrona sin bloquear a OJS.

## 3. Alcance

**Incluye**

- Endpoint `POST /manuscripts` multipart (archivo + JSON de metadatos).
- Validación de tipo (MIME y firma `%PDF-`) y tamaño (≤ 25 MB).
- Modelo `Manuscript` y migración inicial.
- Almacenamiento del archivo en `storage/{manuscript_id}.pdf`.
- Respuesta `202 Accepted` con `manuscript_id` y encolado del análisis.
- Idempotencia: un reenvío idéntico (mismo `submission_id` y `sha256`) devuelve el manuscrito existente.

**No incluye**

- Obtención del PDF desde OJS (US-02).
- Interpretación de sección e idioma (US-03).
- Detección de reenvíos (US-31).

## 4. Entradas

| Entrada | Origen / formato | Restricciones |
|---|---|---|
| `file` | multipart/form-data, `application/pdf` | ≤ 25 MB; debe empezar con `%PDF-`. |
| `metadata` | Parte JSON del multipart | `submission_id` (obligatorio), `section_id`, `title`, `locale`, `revision`, `submitted_at`. |
| Token de servicio | Cabecera `Authorization: Bearer` | Compartido con el plugin; configurado por variable de entorno. |

## 5. Salidas

| Salida | Destino / formato | Descripción |
|---|---|---|
| Respuesta 202 | JSON | `{manuscript_id, status: "received"}`. |
| Respuesta 200 (duplicado) | JSON | `{manuscript_id, status, duplicate: true}` del manuscrito ya existente. |
| Registro `manuscripts` | PostgreSQL | `id (UUID), submission_id, filename, sha256, size_bytes, section_id, locale, title, status, created_at`. |
| Archivo | `storage/{id}.pdf` | Copia íntegra del PDF recibido. |

**Contrato de ejemplo**

```http
POST /manuscripts
Content-Type: multipart/form-data
  file=@manuscrito.pdf
  metadata={"submission_id": 1234, "section_id": 2, "title": "…", "locale": "es_ES", "revision": 1}

HTTP/1.1 202 Accepted
{"manuscript_id": "7f3c…", "status": "received"}
```

## 6. Reglas de comportamiento

1. El archivo se valida por firma binaria además del `Content-Type` declarado.
2. Se calcula `sha256` del archivo y se guarda con el registro.
3. La persistencia del archivo y del registro es atómica: si falla una, no queda la otra.
4. La respuesta se devuelve antes de iniciar la extracción (procesamiento asíncrono).
5. Si ya existe un manuscrito con el mismo `submission_id` y el mismo `sha256`, no se guarda otra copia ni se re-analiza: se responde `200 OK` con el `manuscript_id` y el estado actuales y `duplicate: true` (D-01).
6. Ciclo de estados del manuscrito: `received → extracting → extracted → validating → validated → generating → ready_for_review → in_review → published | no_observations`; estados terminales de excepción: `unreadable`, `out_of_scope`, `failed`.

## 7. Excepciones y flujos alternativos

| Condición | Comportamiento esperado | Ref. |
|---|---|---|
| Archivo no PDF | `400 Bad Request` con `{error: "not_pdf"}`; nada se persiste. | AC |
| Archivo > 25 MB | `413 Payload Too Large`; nada se persiste. | AC Sprint 1 |
| `metadata` ausente o sin `submission_id` | `422 Unprocessable Entity` con detalle del campo. | — |
| Token ausente o inválido | `401 Unauthorized`. | — |
| Fallo de disco o base de datos | `500` y rollback; el plugin registra el error sin bloquear el envío del autor. | RNF-06 |

## 8. Criterios de aceptación

**AC-01**

```gherkin
Dado un PDF válido de 2 MB y metadatos con `submission_id`
Cuando el plugin hace `POST /manuscripts`
Entonces responde `202` con un `manuscript_id` UUID y el registro queda con estado `received`
```

**AC-02**

```gherkin
Dado un archivo `.docx` renombrado a `.pdf`
Cuando se envía al endpoint
Entonces responde `400` y no se crea registro ni archivo
```

**AC-03**

```gherkin
Dado un PDF de 26 MB
Cuando se envía al endpoint
Entonces responde `413` y no se crea registro ni archivo
```

**AC-04**

```gherkin
Dado un envío aceptado
Cuando se consulta `storage/{manuscript_id}.pdf`
Entonces el archivo existe y su `sha256` coincide con el registrado
```

**AC-05**

```gherkin
Dado un PDF ya recibido con el mismo `submission_id`
Cuando el plugin lo envía de nuevo
Entonces responde `200` con el mismo `manuscript_id`, `duplicate: true`, y no se crea un segundo registro ni un nuevo análisis
```

## 10. Notas de diseño

- FastAPI `UploadFile` + `Form`; límite de tamaño también en el servidor ASGI para no leer archivos gigantes a memoria.
- En esta etapa el análisis se lanza con `BackgroundTasks` de FastAPI; más adelante se encolará en Celery + Redis (`agent-worker`) sin cambiar este contrato (D-04).
